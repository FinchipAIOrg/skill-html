结论
报错根因：提问者的 schema 把 references: [id], fields: [subcategoryId] 写在了列表侧。这两个字段属于「真正持有外键的那一侧」，也就是关系表；写进多对多的列表侧，Prisma 就把这段关系读成嵌入式多对多——正是 MySQL 不支持的形式。
线程给出的两种写法：① 隐式关系表——两侧只写 Xyz[] / Kva[]，不写 fields / references，关系表由 Prisma 托管；② 显式关系表——需要往关系上挂自定义字段时才用。
「不建中间表」的正解：做不到。多对多的物理实现必然有一张联结表，这是数据库层约束而非 Prisma 限制。隐式写法的区别只是你不用写它，Prisma 替你建并托管。真正的选择是由谁来写这张表，不是它存不存在。

判断
可采信
作答者 OwO7 是真人，线程内无 APP 机器人标记；报错文本与 schema 结构与提问场景同构；两个写法的代码块完整且自洽——隐式写法恰好去掉了 fields / references，与上面的根因诊断互相印证。
△ 一处如实标注：线程没有给这两种写法排序，原话只说「主要有两种写法」。「不挂自定义字段时隐式写法更省事」是读者推断，不是原文。

结论
根因：Bun 环境下 Prisma 的 generate 需要 node 在 PATH 上——Prisma 依赖一部分 Node API，纯 Bun 不完整兼容，于是进程挂住不退出。
主要解法：在被挂住的机器上装 Node.js。备选：不装 Node，改用 npm 跑 generate。技术解释（来自 Prisma 团队成员 aqrln）：Prisma 并不显式启动 node 进程，而是用 child_process.fork 执行 @prisma/client 里的 generator-build/index.js。
可信度
判断
需核验后采信
本条答案出自机器人，所以核验环节才是重点，实际查出四件事：
① 作答者是 AI 机器人——Prisma AI Help，带 APP 标记。Answer Overflow 的排版不会区分人和机器人，这改变了结果的读法：它是知识源汇编，不是「有人踩过同一个坑」的第一手经验。
② 两个引用链接初查全部 404，但不是伪造。真因是仓库改名 prisma/prisma → prisma/orm，issue 级重定向没被保留（实测跳转次数 0）。用同仓库另一个编号做对照（#21241）同样 404@旧 / 200@新，属系统性行为而非个别链接丢失。换到新址后两个 Issue 标题完全吻合：#25730 已于 2025-03-24 关闭，#21277 至今仍 open。
③ 四条引文逐字回查，全部命中原作评论（含日期与作者）。内容站得住，烂掉的是链接。
④ 机器人漏了一条更省事的解法。原 Issue 里 2025-03-12 的评论给出 bunx prisma generate | cat——去掉 TTY 即可通过，就在这条线程开始的前一天。机器人只字未提。原因：AI 答案是对知识源的快照，看不到晚于它生成的讨论——它的「新」有天花板。
结论：引用链最终闭合，内容可采信，但链接与时效必须自己续上。这类社区索引的真实风险不是内容错，而是链接会烂、答案会过期。

07 · 目标用户与 CTA

给那些已经搜过一轮、但没搜到的人

它不解决「怎么提问」——它解决的是「答案存在，但不在你能搜到的地方」。所以它的适用边界反而很好界定：要么你正好在那个边界内，要么完全用不上。

01

业务开发者

用 Prisma、Drizzle、Next.js 这类工具时撞上隐性行为与版本边界：官方文档讲语法，不讲「在 MySQL 上会怎样」。这里能拿到的是同构场景的判例，不是语法说明。

02

技术支援与提问者

在发出提问之前先自查一遍——这条坑大概率已经有人踩过，并且答案留在了某个服务器的 #help 频道里。先搜一次，能让提问本身更准。

AI Agent 与编码助手

模型训练数据里没有的小众社群实践。关键差别在于输出形态：接上之后每个结论都带一条可点开核对的原帖，而不是「通常来说」。

04

开源维护者

官方 overview 把「开源项目」列为首要目标社区类型。除检索外还有一个反向用法：看用户到底卡在哪一步、用什么语言描述问题。

官方 overview 点名的目标社区类型：开源项目 · 游戏服务器 · 模组服 · 游戏开发 · 作业答疑 · 兴趣社区。需要说明的是，这是「部署 Bot 的社区」口径；本页的读者是 skill 使用者，两者不是同一批人。
适 用
  • 目标库已被索引且有人在用——有判例可找
  • 你需要的是「和我这个场景一模一样」的解法，而不只是语义
  • 你愿意在采信前，追一次官方来源
不 适 用
  • 目标库没进档案（小众、闭源、纯私有）

  • 想查截图、语音讨论或已删除的消息——它们从不进入档案
开 始 使 用

让 AI 在查库问题时，先去翻一遍 Discord 档案

这个 skill 不做别的事，它把一条动作固定下来：限定到档案库的检索 → 命中同构线程 → 抽取结论 → 标出核验目标。没有它，模型只能凭训练数据里的印象作答；接上之后，每条结论都拖着一条能点进去核对的原始线索。
